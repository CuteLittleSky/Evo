## 怎么做（第一版）

- **独立的 ffmpeg 进程**：记录程序开、关它。放进 Windows 的作业对象，Evo 崩了、被结束，它也跟着退，不会一直往硬盘写
- **什么时候录**：一局开始时开始（看到开局画面或自己的界面），一局结束时停（淘汰画面、冠军、返回大厅）。不在对局里不录
- **抓屏**：`gfxcapture=hwnd=<Apex 的窗口句柄>…`，按设置的分辨率在抓的时候缩放。抓不到再换 `ddagrab`
- **找 Apex 的窗口不打开游戏进程**（原则 1）：进程号从进程列表里拿（`game_detect`，本来就不打开进程），窗口用 `recorder.find_window` 按"窗口归哪个进程"找，把窗口句柄交给 ffmpeg。不用 ffmpeg 的 `window_exe`：2026-11-20 看 ffmpeg 源码发现，它要对每个窗口所属的进程（包括 Apex）打开一个查询句柄读程序名（`OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION)`，不读内存，任务管理器也这样，但还是算碰了游戏进程）。11-19、11-20 用 `rec_probe.py` 测"只抓 Apex 窗口"时用过它几次，之后改掉了。Windows Graphics Capture 本身只向 Windows 要这个窗口合成好的画面（和截图工具、Xbox Game Bar 一样），不碰游戏
- **编码**：显卡硬件编码，NVIDIA > AMD > Intel。没有硬件编码器的电脑不开放这个功能（不用 CPU 软编）
- **写文件**：每开一次 ffmpeg 写一个 MPEG-TS（程序崩了也不会坏；`-mpegts_copyts 1` 让文件里的时间戳就是原来的时刻），断了重开就再写一个。一局结束首尾相连地读（`concat:` 协议）拼成一个 MP4，不重新编码。拼的时候加 `-copyts -start_at_zero -dts_delta_threshold 1000000`：断掉的空档原样保留，不然 ffmpeg 会把 10 秒以上的空档挤掉，后面的事件就对不上了。整局录像不用切成 2 秒一段（剪高光时再切）
- **崩了以后**：上次没拼完的分段文件，下次拼成名字带"_未完成"的 MP4（只有画面）
- **时间**：每一帧的时间戳 = 抓到它时电脑的时钟减去开始时刻（微秒），所以事件的时刻能直接对上录像里的位置
- **断了就重开**：切窗口、切显示模式、弹管理员确认框时桌面复制会失效，ffmpeg 直接退出、不会自己恢复。马上重开（第一次可能被拒，再开一次），实测断 1–2.5 秒。Windows Graphics Capture 遇到这些时怎么样，要在对局里实测
- **声音**：按进程录音（`tools/rec_audio.py` 的做法），每一包带 Windows 给的时刻，拼 MP4 时按这个时刻对齐画面
- **事件**：
  - 倒地 `knocked`、被扶起 `revived`、成盒 `dead`、被复活 `respawned`、冠军 `champion`：看 InMatchWatcher 记下的状态，不另外认画面
  - 击倒对手 `knock`（11-20，用户的提示）：画面中间那一行"击倒 名字 +150"，在一条横带里找"击倒"两个字（只比外观，录像开着时每截一张看一次，约 1 毫秒；`hud.knock`，规则 `config/hud.json` 的 knock，实测见 `docs/识别经验.md`"中间那一行'击倒'"）。没看到 0.6 秒以上才算下一次；还在显示但左右挪了 20 以上（换了名字）也算。用 11-20 那局的录像整段验过：只认出一次，时刻对。别的击倒、16:9、助攻要用下一局实测
  - 击杀 `kill`（11-20；用户提醒：击倒是把敌人打倒地，击杀是把倒地的补掉、或者直接打掉对方小队最后一个人，两种分开标）：和 Evo 一贯的"对局中只存、赛后才读"一样。对局中先找右上角击杀那一行的骷髅图标（`hud.kill_cell`），只看它右边那个数字的白字，变了才存下这一行（`hud.kp_snip`，约 40 KB）和时刻；回到大厅后每截一张读两块（`hud.read_kills`，用识别引擎），击杀数比上一块大就是一次击杀（一下子多两个记"×2"），写进那一局的 `.json`；读错的不标（`match_recording.kill_events`）。停止记录时没读完的一次读完。不解码录像，时刻精确到截图的间隔（0.3 秒）。不能看整个击杀那一行：它背后是半透明的底，跟着画面一直变（11-20 那局几乎每帧都算变了），而且这一行靠右排、跟着后面几项左右挪（骷髅图标在基准 x 1575 左右），所以先找图标。用 11-20 那局录像按记录程序的节奏模拟：整局只存了 3 块（读 0.4 秒），标出一次击杀在 155.1 秒（击倒在 149.4 秒，先打倒、6 秒后补掉），和战绩的击杀 1 对得上
  - 助攻 `assist`（11-20 用户要的，做法和击杀一样）：同一行握手图标右边的助攻数（`hud.kp_cells` 同时给击杀、助攻两格，有一格变了就存这一行；`hud.read_kp` 一块读两个数，`match_recording.count_events` 各算各的），一下子多两个也记"×2"。录像页上是粉色。用 11-20 那局模拟：这局助攻 0，没有标；存下的块从 3 变成 10（助攻那一格的"0"背后亮时也算变了，读 10 块 0.8 秒，不影响）。还没在真有助攻的局里验证过。画面中间那一行的"助攻，击倒 名字"现在还会被算成一次击倒（找的是"击倒"两个字），要分开得有一张真画面当参照图
- **一局从哪到哪**：看到开局画面（或第一次看到自己的界面，靶场没有开局画面）开始，结算画面、回到大厅以后再录 3 秒停。拼 MP4 在后台线程里做，不耽误读结算画面。录像和战绩页的局按时间对上（`.json` 里有开始、结束的时刻），不改数据库
- **存在哪**：数据文件夹里的 `recordings\年-月\`。每局一个 MP4，加一个同名的 `.json`（哪一局、事件和时刻、画质设置）。**不改数据库表**
- **页面**："录像"页：播放（WebView2 自带的播放器），进度条上标事件，点事件跳过去；战绩页每一局能跳到它的录像
- **设置页**：开关（默认关）、画质、硬盘上限、保存位置

## 实测踩过的坑（照着做）

- 时间戳要用微秒（`-enc_time_base:v filter`），不能取整到 1/60 秒：取整后有的帧撞在同一个时刻被丢掉
- 把分段接起来要首尾相连地读（`concat:` 协议），不能用 ffmpeg 的拼接列表：时间会越接越偏
- 从录像里按时间取一帧用 `select` 滤镜 + `-fps_mode passthrough`，不用 `-ss`
- 存图、读图不要用 `cv2.imwrite` / `cv2.imread`：路径里有中文时会悄悄失败
- 在录像上读界面要按游戏自己的画面比例找位置（`game_aspect.py`）：拉伸分辨率时只按截图的比例找会读不出
- EA 反作弊在运行时，管理员也开不了 Windows 的事件记录（ETW），PresentMon 量不了帧数；桌面复制、Windows Graphics Capture、按进程录音都不受影响
