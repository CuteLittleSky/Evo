# 录屏实测（高光录屏第 0 步）

2026-11-19 起。要不要做"高光自动录屏"、怎么做，先用实测的数来定。方案是：一个独立的 ffmpeg 进程，用桌面复制抓屏（和 dxcam 同一个接口，不碰游戏），显卡硬件编码，2 秒一段存在硬盘上，由 Evo 认出的事件决定留哪几段。还没定的事见 todo.md"高光录屏"那条。这一步只在测试时用 ffmpeg，Evo 本身不改。

- 工具：`tools/rec_probe.py`（录屏、量开销、比对），`tools/rec_audio.py`（只录一个程序的声音）
- 录下的东西放在 `captures/rec_probe/<时间>/`：不进 git，很大，测完就删
- 下面的 `python` 都是指 `E:\Evo\.venv\Scripts\python.exe`，在 `E:\Evo` 里运行

## 已经在本机试过的（不开游戏）

2026-11-19，RTX 5060 Ti（屏幕接在它上面）+ AMD 核显，2560×1440 240Hz，ffmpeg 9.0.2，桌面基本不动。

| 项目 | 结果 |
| --- | --- |
| 抓屏 | 桌面复制（ffmpeg 的 `ddagrab`）、Windows Graphics Capture（`gfxcapture`）都抓得到整个屏幕 |
| 编码器 | `h264_nvenc`、`hevc_nvenc`、`av1_nvenc` 都能直接拿显卡里的画面编码。AMD 核显的 AMF 只能先拷进内存再编码（正常：屏幕接在 N 卡上） |
| 缩到 1080p | 在显卡上缩放（`scale_d3d11`）建不起来（"Could not create the texture"），CUDA 也接不上，所以第一版录原分辨率 |
| 只录屏 | ffmpeg 占 CPU 约 4% 个核，内存 81 MB，每秒 59.9 帧（设定 60） |
| 录屏，同时每 0.3 秒给 Evo 送一张原图（"不用 dxcam、从 ffmpeg 拿图"的想法） | ffmpeg 占 CPU 6.9% 个核，内存 125 MB；Python 这边收图 7.4% 个核。**录像只剩每秒约 56 帧，少了约 6%**：从显卡拷图和抓屏在 ffmpeg 的同一个线程里，拷图时抓屏要等。原图里加转成 BGR 那一步时 ffmpeg 占 15.5%，已改成不转换 |
| 模拟读结算页（引擎读一整张图，5–8 秒） | 收图的线程一直在读：两张原图之间最长隔 0.36 秒，录像没受影响 |
| 两个抓屏放进同一个 ffmpeg | 不行：同一个程序对同一块屏幕只能开一次桌面复制。所以要从 ffmpeg 拿图，只能把同一路画面分成两路 |
| 只录一个程序的声音 | 能用（Windows 的按进程录音）。每一包声音带着 Windows 给的时刻 |
| 声音和画面对齐 | 画面和声音各自的时刻都准：方块变白后 5–21 毫秒录进画面（一帧之内）；嘀声 28–59 毫秒后录进声音（这是 Windows 播放声音本身的延迟）。剪出来的片段里声音比画面晚 27–39 毫秒，看不出来 |
| Evo 崩了，ffmpeg 会不会一直录 | 不会：ffmpeg 放进了 Windows 的"作业对象"，Evo 被强行结束时它也跟着退 |
| 对照：dxcam 每 0.3 秒截一张 | 源码版（`python.exe`）占 415% 个核，就是 todo"源码版截屏时 CPU 很高"那条，不能当对照。dxcam 的开销看安装版日志里的"占用"（11-10 是 15%） |
| 录像里的小字 | 拿 `captures/samples/对局中.png` 编码成录像再读右上角：剩余小队 18、RP −65，和原图一样。这是静止的画面，比实战乐观，要用实战录像再比 |

脚本里已经处理好的两个坑：
- 时间戳要用微秒，不能取整到 1/60 秒：取整后有的帧撞在同一个时刻被丢掉，录像只剩 58.7 帧
- 把分段接起来时要首尾相连地读（`concat:` 协议），不能用 ffmpeg 的拼接列表：拼接列表按每段的"时长"排下一段，帧间隔不均匀时每段差两三毫秒，10 秒就偏了十几毫秒

## 准备

1. **ffmpeg**：本机已经用 winget 装了 `Gyan.FFmpeg` 9.0.2，脚本自己找得到。别的电脑上用 `winget install --id Gyan.FFmpeg -e` 装，或者设环境变量 `EVO_FFMPEG` 指向 ffmpeg.exe。这个完整版的 ffmpeg.exe 有 217 MB，只在测试时用
2. **PresentMon**（量帧数，Intel 开源；只读 Windows 的事件记录，不碰游戏）：在 GitHub `GameTechDev/PresentMon` 的 Releases 里下载 `PresentMon-2.6.0-x64.exe`（约 1 MB）。要在**管理员身份**的 PowerShell 里运行
3. **开安装版 Evo**（`E:\Evo Tracker`）照常记录：第一版就是"Evo 用 dxcam 截图，另开一个 ffmpeg 录屏"。不要同时开源码版
4. **硬盘**：游戏里画面一直在动，按 22 Mbps 算，每 10 分钟约 1.6 GB

## 步骤

### 1. 看能用什么（开着 Apex，约 2 分钟）

```
python tools/rec_probe.py check
```

记下哪些编码器打了 ✓，以及"gfxcapture 只抓 Apex 的窗口"能不能用。最后一行会给出下一步的命令。

### 2. 帧数（靶场，约 15 分钟）

1. 进靶场，站在一个固定位置看同一个方向，不动鼠标。画质设置和平时一样
2. **关录屏**，在管理员 PowerShell 里量 60 秒。`--delay 15` 是留 15 秒切回游戏：

   ```
   .\PresentMon-2.6.0-x64.exe --process_name r5apex.exe --process_name r5apex_dx12.exe --output_file off1.csv --delay 15 --timed 60 --terminate_after_timed
   ```

3. **开录屏**：在另一个窗口运行 `python tools/rec_probe.py record --minutes 3 --label 靶场`，等它说"开始录"以后，用同样的 PresentMon 命令量，文件名换成 `on1.csv`
4. 关、开再各量一次（`off2.csv`、`on2.csv`），交替着量，免得显卡越跑越热影响结果
5. 比较：

   ```
   python tools/rec_probe.py fps --off off1.csv off2.csv --on on1.csv on2.csv
   ```

6. 想单独看"给 Evo 送图"的影响：开录屏那一步改用 `record --no-frames`，再量一组

**过关**：平均帧数和 1% 低帧都只掉 3% 以内（方案建议的门槛，你来定）。

### 3. 打两局真实对局（每局约 25 分钟）

```
python tools/rec_probe.py record --minutes 25 --label 对局1
```

- 开局前开始录，打完自动停。也可以按 Ctrl+C 提前停
- 默认同时录 Apex 的声音、每 0.3 秒给 Evo 送一张原图、每 15 秒存一张原图。"读结算页时送图会不会堵住"已经在本机试过（加 `--ocr-every 60` 可以再试），对局中别开：引擎一读就占好几个核，游戏会卡一下
- 打的时候故意做几件事，看录屏断不断、断了能不能自己接上：
  - Alt+Tab 切出去再切回来，做一次
  - 在大厅里把显示模式在"全屏"和"无边框窗口"之间切换一次
  - 弹一次管理员确认框（比如右键以管理员身份打开记事本），做一次
- 停下后会打印结果，也存在那次录像文件夹的 `summary.txt` 里：ffmpeg 的 CPU 和内存、文件多大、录像里每秒实际几帧、送图有没有断、断了又重开了几次
- 第二局用 `--no-frames` 打，对比不送图时的开销

**过关**（方案建议的门槛，你来定）：
- ffmpeg 只录屏时占不到 5% 个核
- 录像每秒帧数在设定的 95% 以上
- 切窗口、切显示模式以后几秒内自己接上

### 4. 录像里的小字读不读得准（打完第 3 步以后）

```
python tools/rec_probe.py ocr captures\rec_probe\<第3步的文件夹>
```

它把对局中每 15 秒存的那张原图，和录像里同一时刻的那一帧，都拿 Evo 读右上角的方法读一遍，逐项比较剩余小队、击杀、助攻、伤害、RP。

**过关**：全部一样。不一样的地方，就是以后"赛后看录像再识别"会读错的地方。

### 5. 声音

1. **漂不漂**（不用开游戏，10 分钟）：

   ```
   python tools/rec_probe.py avsync --seconds 600
   ```

   - 屏幕左上角会出现一个黑方块，每 2 秒闪白一下、嘀一声
   - 期间别把别的窗口拖到它上面，也别关声音
   - 结果会告诉你声音比画面晚多少、每 10 分钟漂多少
   - **过关**：漂移在 20 毫秒以内
2. **游戏里听**：第 3 步录的时候打完一波交火，按 Ctrl+C 停，再剪最后 30 秒、打开播放：

   ```
   python tools/rec_probe.py clip captures\rec_probe\<文件夹> --last 30 --open
   ```

   看枪声和开火的画面对不对得上，声音有没有断断续续。也可以用 `--at 秒数` 剪中间的某一段（秒数从开始录算起）。

### 6. 可选

- **只抓 Apex 的窗口**（如果第 1 步说能用）：`record --source gfxcapture --minutes 5`，看会不会有黄边、QQ / 微信弹窗还录不录得进去、占用和桌面复制比怎么样
- **双显卡笔记本**：在笔记本上跑 `check`，看用核显编码（Intel 是 `h264_qsv`）能不能直接拿显卡里的画面
